# Images

## Logo

The real brand is in place. Every file below is generated from the masters in
`brand/` by `brand/build-site-assets.py` — **don't hand-edit them**, change the
master and re-run the script (see `brand/README.md`).

| File | What it is |
| --- | --- |
| `logo-horizontal-256.png` / `.webp` | Horizontal lockup, no tagline, black wordmark — 1x header/footer |
| `logo-horizontal-512.png` / `.webp` | Same, 2x retina |
| `logo-horizontal-light-256.png` / `.webp` | Wordmark knocked out to white for the charcoal footer — 1x |
| `logo-horizontal-light-512.png` / `.webp` | Same, 2x retina |
| `og-card.png` | 1200x630 share card — tagline lockup on a full-bleed gold field |
| `lrd-tag.svg` | Builder credit tag in the footer bottom bar. Not a Happy Construction asset; copied verbatim from `funcitygamesnwa-site` so the credit is identical across client sites, and not produced by `build-site-assets.py`, so leave it out of any regeneration sweep. |

Both logo variants are 256x78 intrinsic (the lockup is 3.32:1). The icon set
(`/favicon.svg`, `/favicon.ico`, `/icon-*.png`, `/apple-touch-icon.png`) is
generated by the same script but lives at the repo root.

`js/components.js` renders both variants through a `logoPicture()` helper that
emits a `<picture>` with a WebP `<source>` and a PNG fallback plus a 2x
`srcset`. Change the paths there, not in each page.

**Keep the header logo's height definite.** `.header-logo` sets an explicit
`height` (not `max-height`) because the logo lives in a flex row — an image
sized `width: auto; max-height: N` there has no definite flex basis and
collapses to 0x0. The `<picture>` wrapper is also forced to `display: block` for
the same reason. The `width`/`height` attributes on the `<img>` must stay at the
raster's true 256x78 so there's no layout shift.

## Share cards

`og-card.png` is referenced by `og:image` / `twitter:image` on all five pages,
with `og:image:type` set to `image/png`. **Keep it PNG, not WebP** — several
link-unfurl pipelines reject WebP and fall back to a no-image card. Both
`og:image:alt` and `twitter:image:alt` are set; keep them in sync if the card
art changes.
